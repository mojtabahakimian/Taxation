# شیم SDK مؤدیان — فقط برای اجرای تست روی لینوکس

## چرا وجود دارد

`Prg_Moadian.csproj` به بستهٔ `TaxCollectData.Library` نسخهٔ **0.0.34** ارجاع
می‌دهد. این نسخه روی nuget.org نیست (آنجا فقط 0.0.4 هست) و فقط روی ماشین
ویندوزی توسعه‌دهنده موجود است. پس روی لینوکس/CI هارنس `TestTools/LocalMoadian`
اصلاً restore نمی‌شود.

این پوشه زیرمجموعه‌ای از API عمومی آن SDK را که `Prg_Moadian` و هارنس واقعاً
استفاده می‌کنند، با همان namespace و همان نام‌ها بازسازی می‌کند:

| فایل | محتوا |
|---|---|
| `Dto.Content.cs` | DTOها (`InvoiceDto`، `InvoiceHeaderDto`، …)، `PacketResponse`، `HttpResponse<T>`، `SignatoryConfig`، `NormalProperties`، `ClientType` |
| `Business.cs` | `TaxApiService.Instance`، `TaxApis` (پروتکل HTTP)، `TaxIdGenerator` (+ Verhoeff)، `TaxApiException` (internal، مثل SDK واقعی) |
| `Crypto.cs` | RSA-OAEP-SHA256 + XOR + AES-GCM با IV شانزده‌بایتی (BouncyCastle)، و سریال‌سازی JSON صورتحساب |
| `NoDbStub.cs` | وصلهٔ زمان اجرا برای نبودِ `C:\correct\CNR.udl` (پایین‌تر) |
| `FakeDb.cs` | دیتابیس ساختگی درون‌حافظه روی SqlClient، فقط وقتی گروه ۲۹ فعالش کند (توضیح در `TestTools/LocalMoadian/README.md`) |

پروژهٔ `TestTools/ShimBuild/MoadianLocalTest.Shim.csproj` هارنس + سورس
`Prg_Moadian` + این پوشه را در **یک** اسمبلی به نام `MoadianLocalTest` می‌سازد.
هیچ فایل اصلی (نه `Prg_*` و نه `TestTools/LocalMoadian`) تغییر نمی‌کند.
هدف net8.0 است چون روی ماشین لینوکسی فقط runtime 8 نصب است.

```bash
bash TestTools/run-tests-linux.sh             # سرور ساختگی + هارنس، بدون دیتابیس
bash TestTools/run-tests-linux.sh --port 9191 # پورت دیگر
```

## ⚠️ هرگز منتشر نشود

روی ماشین ویندوزی توسعه‌دهنده **SDK واقعی** استفاده می‌شود
(`run-tests.ps1` و `MoadianLocalTest.csproj` دست‌نخورده‌اند). این شیم نباید
به هیچ پروژهٔ تولیدی ارجاع داده شود و خروجی `ShimBuild` نباید جایی کپی شود:
به سامانهٔ واقعی فقط «شبیه» حرف می‌زند و هیچ‌وقت در برابر آن آزموده نشده.

## محدودیت صادقانه

زیر این شیم، لایهٔ **SDK → سیم** بازنویسی خود ماست. سرور ساختگی
(`moadian_mock.py`) هم بازنویسی ماست. پس:

- گروه ۱۷ (قالب JSON و رمزنگاری روی سیم) زیر شیم فقط نشان می‌دهد
  **شیم با سرور ساختگی سازگار است** — نه اینکه SDK واقعی یا سامانهٔ واقعی
  همین را می‌فرستد/می‌پذیرد. ۱۷-۱ تا ۱۷-۳ (وجود فیلدها و `Insr: int?`) هم
  فقط شیم را می‌سنجند، نه 0.0.34 واقعی را.
- گروه‌های ۳ تا ۱۵ و ۲۶ منطق **برنامه** را می‌سنجند؛ مسیر انتقال زیرشان شیم است.
- گروه‌های آفلاین (۱، ۲، ۲۰، ۲۳، ۲۷) به SDK وابسته نیستند و همان اعتبار ویندوز را دارند.

آنچه شیم از آن گرفته شده:
- پروتکل و رمزنگاری: `moadian_mock.py` (مسیرها، ساختار پاکت، XOR/GCM).
- نام، ترتیب و nullها در JSON: `golden/*.json` که با SDK واقعی ضبط شده‌اند.
- الگوریتم taxid: SDK عمومی؛ رقم کنترل روی ۳ شماره مالیاتی واقعیِ مانده در
  کامنت‌های مخزن درست درمی‌آید. محاسبهٔ «روز» (UTC/محلی) قطعی نیست.
- امضا: RSA-SHA256-PKCS1 روی رشتهٔ نرمال‌شده؛ سرور ساختگی فقط وجودش را می‌سنجد،
  پس درستی امضا اینجا آزموده **نمی‌شود**.

## NoDbStub — چرا و چه می‌کند

سازندهٔ `CL_CCNNMANAGER` فایل `C:\correct\CNR.udl` را می‌خواند و بلافاصله
`SELECT GETDATE()` می‌زند؛ `CL_MOADIAN` آن را در سازندهٔ استاتیک می‌سازد. گروه ۲۰
(که آفلاین است) به `CL_MOADIAN.ResetState()` دست می‌زند و بدون دیتابیس کل
پروسهٔ هارنس با `TypeInitializationException` می‌میرد (کد خروج ۱۳۴).

در این ساخت، **فقط اگر آن فایل خواندنی نباشد**، سازنده با Harmony جایگزین
می‌شود: رشتهٔ اتصال به یک آدرس مرده اشاره می‌کند و اتصالی زده نمی‌شود. هر کوئری
واقعی همچنان شکست می‌خورد (یعنی «دیتابیس در دسترس نیست»، نه دیتابیس ساختگی).
با `MOADIAN_SHIM_NO_DB_STUB=0` خاموش می‌شود.

## پایتون

`run-tests-linux.sh` اولین پایتونی را برمی‌دارد که `cryptography` در آن واقعاً
import شود (`$PYTHON`، سپس python3، python3.12، …). روی ماشین فعلی `python3`
نسخهٔ 3.11 است و بستهٔ دبیانی `cryptography` برای 3.12 ساخته شده، پس 3.12
انتخاب می‌شود.
